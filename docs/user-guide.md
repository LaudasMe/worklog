# workLog 用户指南

本指南适用于 workLog v0.4.0。workLog 记住项目和任务做到哪里、接下来做什么。你可以在 Codex 记进展，再在 OpenCode 或另一个 Codex 会话读回原文并继续。

| 你想做什么 | workLog 会做什么 |
| --- | --- |
| 给项目启用 workLog | 在你指定的项目目录里创建数据库。 |
| 新建任务 | 保存任务标题，给它分配编号，比如 `T001`。 |
| 从项目目录继续工作 | 列出任务摘要，再读项目目标、任务进度、决定、未决问题、待办和阻塞。 |
| 看任务进展 | 显示谁在跟进、最近记了什么、下一步是什么。需要时可以查看 Markdown 原文。 |
| 开始任务 | 保存显式开始记录。需要专人跟进时可另行接手，接替其他会话前需确认。 |
| 留下进度和交接说明 | 保存一段摘要、详细内容和下一步。详细内容可以有中文、列表和代码块。 |

## 从当前项目接着做

可以先从 workLog 源码目录创建下面这个临时示例项目，并按[安装说明](skill.md)安装 v0.4.0 Skill。示例已有 T001、一条待办和一个阻塞，并带有可复算的订单数据。

```sh
DEMO="$(mktemp -d)"
git -C "$DEMO" init
python3 -B examples/context_seed.py "$DEMO"
printf '%s\n' "$DEMO"
```

1. 从示例项目根目录开一个新会话，加载 `worklog`。先请它「用任务摘要找出当前项目里在进行的任务，读项目和任务上下文，告诉我待办、阻塞和依据」。它应找到 T001 并读到零金额复测。
2. 再请它「按 T001 的待办实际运行验证，保存结果。通过后在一次写回里记录进展、完成待办并解除对应阻塞」。结果应为 `2 + 3 + 0 = 5`，样本中仍待决定的问题继续保留。
3. 从同一项目根目录另开一个会话，请它「只读复查最新进展、已关闭的待办与阻塞、未决问题，再查回旧决定的原文」。两个会话都以项目目录定位同一个数据库。

旧库可以先看摘要和历史。需要读公开接口或使用 schema 4 的任务操作时，请按[备份和升级步骤](context-cli.md#备份和升级)操作。如果另一会话正在跟进任务，请先确认是否接替。命令和 JSON 示例见[上下文 CLI](context-cli.md)。

## 从建任务到换客户端接着做

先选一个已经存在的项目文件夹。下面的 `<项目根目录>` 用该文件夹的完整路径替换。「示例项目」可改成你自己的项目名。空项目的第一条任务通常是 `T001`，以后以实际返回的编号为准。

### 1. 在 Codex 启用项目并建任务

> `$worklog` 初始化 `<项目根目录>` 的 workLog，名称用「示例项目」。再建一条任务「核对订单合计」。

### 2. 接手并记录进展

在同一个会话接手任务，再把已经确认的结果记下来。

> `$worklog` 接手 `<项目根目录>` 的 T001，先告诉我当前进展。

> `$worklog` 给 `<项目根目录>` 的 T001 记一条进展。核对了两笔示例订单，金额 2 和 3，合计为 5。下一步加入一笔零金额订单，再算一次。

如果有需要保留的 Markdown 或代码块，可以把原文一并贴给它。

### 3. 交接给 OpenCode

在原来的 Codex 会话结束跟进，写清下一步。

> `$worklog` 交接 `<项目根目录>` 的 T001。下一位先加入一笔零金额订单，再核对合计。

在 OpenCode 新会话查看交接。确认要继续时，再发接手请求。

> `@worklog` 查看 `<项目根目录>` 的 T001，读回最近交接的原文和下一步。

> `@worklog` 接手 `<项目根目录>` 的 T001。

完成下一步后，可以在这个 OpenCode 会话继续给同一个 T001 记进展。

## 平时只看看

> `$worklog` 查看 `<项目根目录>` 的 T001，只读取，告诉我最近进展和下一步。

也可以让它列出一个项目里已有的任务。想看两个项目里同为 T001 的任务时，把两个项目路径分别写清楚。

## 文件放在哪里

数据库在 `<项目根目录>/.worklog/worklog.sqlite3`，由你明确要求初始化时创建。Codex 和 OpenCode 指向同一个项目文件夹，就能读到相同记录。每个项目单独编号，所以两个项目都可以有 T001。用 Git 管理项目时，可以把 `.worklog/` 加入这个项目的 `.gitignore`。

## 任务状态怎么看

| 界面或输出里的状态 | 意思 |
| --- | --- |
| `TODO` | 待开始。 |
| `IN_PROGRESS`，有会话在跟进 | 该会话可以记进展和交接。 |
| `IN_PROGRESS`，当前接手为空 | 已开始，当前无接手。需要时可接手。 |
| `PAUSED` | 暂停。可以交接，下一会话接手后仍保持暂停。 |
| `BLOCKED` | 有仍生效的任务级阻塞。解除后恢复显示基础状态。 |
| `DONE` | 已完成，可查看完成范围和依据。 |
| `CANCELLED` | 已取消，旧记录保留。 |

已完成或取消的任务可以归档。重开后回到待开始，并退出归档。已完成任务中仍开放且有效的待办继续生效。已取消任务的历史待办和阻塞可按需带回。优先级可设为 p0 至 p3。没填时显示「未设置」。

## 遇到提示怎么办

| 提示 | 你可以怎么做 |
| --- | --- |
| 项目尚未初始化（`not_initialized`） | 先核对目录。首次使用时，明确要求初始化。 |
| 找不到任务（`task_not_found`） | 核对项目路径和任务编号，也可以先请它列出该项目的任务。 |
| 任务已有其他会话跟进（`claim_conflict`） | 先查看最近记录。决定接替时，明确告诉客户端。 |
| 跟进已结束，或任务已被更新（`stale_run`、`revision_conflict`） | 重新查看任务，再决定是否接手或继续写。 |
| 当前命令需要更新数据库（`upgrade_required`） | 用本地 `context` 核对版本，再按[备份和升级步骤](context-cli.md#备份和升级)操作。 |
| 没收到保存结果，或数据库忙（`database_busy`） | 请客户端使用同一个操作 ID 和相同内容重试。已经保存过的请求会返回原结果，避免重复记录。 |

[安装说明](skill.md)介绍怎么让客户端找到 Skill。[CLI 说明](cli.md)适合直接用终端的人。[只读接口说明](read-protocol.md)介绍怎么把数据读到其他工具里。
