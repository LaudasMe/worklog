# workLog 用户指南

适用于 workLog Skill v0.1.0 和 CLI 公开协议 1.0。workLog 把工作进展保存在项目里。你可以在 Codex 记下做到哪里，再打开 OpenCode，读回同一个任务的原文和下一步。

## 目前能做什么

| 功能 | 使用方式 |
| --- | --- |
| 为项目启用 workLog | 对一个已有的项目目录明确执行初始化，得到项目专用的本机 SQLite 数据库。 |
| 建立任务 | 给出任务标题，workLog 分配项目内编号，如 `T001`。 |
| 查看任务和原文 | 按编号查看状态、当前接手会话、最新进展和最近交接。需要细节时可读回保存的 Markdown 原文。 |
| 接手任务 | 在当前会话建立接手记录。若另一会话正在接手，由你确认是否接替。 |
| 记录阶段进展 | 保存简短摘要、Markdown 正文和下一步。Markdown 可以包含中文、列表和代码块。 |
| 交接给下一会话 | 保存交接说明和下一步，结束当前会话的接手。下一会话可以读回并接手同一条任务。 |
| 给其他工具提供只读数据 | CLI 能返回项目身份、任务快照、增量和记录原文。集成方可按快照水位读取后续变化。 |

## 在 Codex 和 OpenCode 里上手

在新会话里，Codex 用 `$worklog`，OpenCode 用 `@worklog`。将示例中的 `<项目根目录>` 换成项目的实际绝对路径，并以回执中的任务编号为准。

### 1. 初始化项目并创建第一条任务

在 Codex 明确提出两项操作。

> `$worklog` 初始化 `<项目根目录>` 的 workLog，项目名为「订单样例」。再新建任务「核对订单合计」。

空项目的第一条任务会得到 `T001`，状态为 `TODO`。以后可以直接用项目路径和任务编号查看这条任务。

### 2. 接手并记下阶段结果

在同一个 Codex 会话里先接手。

> `$worklog` 接手 `<项目根目录>` 的 T001，先告诉我当前进展和最近交接。

准备好结果后，在当前接手会话记录进展。

> `$worklog` 给 `<项目根目录>` 的 T001 记录进展。已核对两笔样例订单，金额 2 和 3，合计为 5。下一步是加入一笔零金额订单并重算。

如果有固定的 Markdown 文本、命令和输出，可以随请求提供，并说明哪些内容要原样保存。

### 3. 交接后换到 OpenCode 继续

在原来的 Codex 会话发出交接请求。

> `$worklog` 交接 `<项目根目录>` 的 T001。写明两笔订单已核对，下一位先加入一笔零金额订单，再核对合计。

打开 OpenCode 新会话，先读上一次交接。

> `@worklog` 查看 `<项目根目录>` 的 T001，读回最近交接的原文和下一步。

确认要继续时，在这个 OpenCode 会话接手。

> `@worklog` 接手 `<项目根目录>` 的 T001。

完成下一步后，在持有接手的会话继续记录进展。任务仍使用 `T001`，新的进展会保存在同一条任务下。

### 4. 只看进展

> `$worklog` 只读查看 `<项目根目录>` 的 T001。请告诉我当前接手会话、最新进展和下一步。

需要项目级概览时，可以请 Skill 用只读快照列出项目里的任务。要看两条同号任务，就分别给出两个已确认的项目路径。

## 数据保存和任务状态

- 每个明确初始化的项目使用 `<项目根目录>/.worklog/worklog.sqlite3`。其中保存项目身份、任务、进展和交接。
- 两个客户端指向同一个项目根时使用同一数据库。两个项目分别初始化后可以各有一条 `T001`。记错或省略项目路径时，先确认对应的项目，再执行查询或写入。
- 在 Git 项目里，可以把 `.worklog/` 加入该项目的 `.gitignore`，让工作记录留在本机。

| 你看到的状态 | 含义 |
| --- | --- |
| `TODO` | 任务已创建，处于待接手状态。 |
| `IN_PROGRESS` 且有当前接手 | 某个会话正在接手，记录进展和交接都使用这次接手。 |
| `IN_PROGRESS` 且当前接手为空 | 任务已交接，下一会话可以继续接手。 |

v0.1 的任务动作覆盖创建、接手、记录和交接，状态范围是 `TODO` 与 `IN_PROGRESS`。自动补记、客户端事件钩子和可视化看板属于后续范围。

## 常见情况

| 情况 | 怎么处理 |
| --- | --- |
| 提示项目未初始化 `not_initialized` | 核对项目路径。首次使用时明确要求初始化，之后再建任务。 |
| 只给了 `T001`，客户端问是哪个项目 | 补充项目的绝对路径。同一个编号可以出现在不同项目中。 |
| 提示任务找不到 `task_not_found` | 确认项目和实际任务编号，也可先查看该项目的任务快照。 |
| 任务已有接手会话 `claim_conflict` | 先看当前接手与最近记录。决定转交后，再明确确认接替。 |
| 接手已结束、被接替或任务版本有变化 `stale_run`、`revision_conflict` | 先读回任务和最近交接，核对现状后决定是否接手或继续操作。 |
| 写入回执丢失或提示数据库忙 `database_busy` | 请客户端用原操作 ID 和相同请求重试。若原操作已成功，CLI 返回原回执，避免重复入库。 |
